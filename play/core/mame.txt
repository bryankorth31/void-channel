Each pack was boot-tested on this PC (node, sound off) with every one of its games among the Internet Archive's most-played
arcade items (100,000 plays or more): each booted, drew its attract screen, and with a coin and a start reached play or
its own start screen; the results are in the PLAY audit folder.

Build command, run in the MAME folder from Git Bash with emsdk active (EMSCRIPTEN pointing at emsdk/upstream/emscripten),
with EMCC_CFLAGS set as below:
EMCC_CFLAGS=-sEXPORTED_FUNCTIONS=@<exports file>
make -j14 BUILDDIR=build-os OPTIMIZE=s SUBTARGET=<name> SOURCES=<driver .cpp files> NO_USE_PORTAUDIO=1 NO_USE_MIDI=1 \
  PYTHON_EXECUTABLE=<python 3> CLANG_VERSION=24.0.0 CC=$EMSCRIPTEN/emcc CXX=$EMSCRIPTEN/em++ AR=$EMSCRIPTEN/emar \
  NOWERROR=1 REGENIE=1 PRECOMPILE=0 "ARCHOPTS_CXX=-include cstdlib -include cmath -include vector"
Why the extra settings: CLANG_VERSION because MAME's makefile cannot read Emscripten's version on Windows; NOWERROR because
this compiler is newer than MAME's code and warns more; the three -include flags supply standard headers newer libc++ no
longer pulls in by itself; PRECOMPILE=0 because a precompiled header must be the first include. None changes MAME's code.
It writes <name>.js and <name>.wasm in the MAME folder; the notice line at the top of each served .js is added by hand
when copying it into play/engine/mame/. The .wasm is stored gzipped, because Cloudflare Pages serves no file over 25 MiB
and a 68000 engine is 26 to 31 MiB plain (about 6 MB gzipped); the arcade runner unpacks it in the browser:
gzip -9 -n -c <name>.wasm > play/engine/mame/<name>.wasm.gz
(-n leaves out the file name and time, so the same engine always gives the same bytes.)

Battery memory (a game's own high scores and settings): MAME writes it only when it exits, and the web build never exits,
so the page calls MAME's own running_machine::nvram_save() itself. MAME's web build does not export that function, so the
exports file adds it to MAME's own export list (scripts/genie.lua, EXPORTED_FUNCTIONS), one name a line:
_main
_malloc

__ZN15running_machine17emscripten_get_uiEv
__ZN15running_machine20emscripten_get_soundEv
__ZN15mame_ui_manager12set_show_fpsEb
__ZNK15mame_ui_manager8show_fpsEv
__ZN13sound_manager4muteEbh
__ZN15running_machine15emscripten_saveEPKc
__ZN15running_machine15emscripten_loadEPKc
__ZN15running_machine21emscripten_hard_resetEv
__ZN15running_machine21emscripten_soft_resetEv
__ZN15running_machine15emscripten_exitEv
__ZN15running_machine10nvram_saveEv
emcc adds EMCC_CFLAGS last to every command, so this list replaces MAME's at the link; MAME's code and build scripts are
not changed. The page calls Module.__ZN15running_machine10nvram_saveEv(Module.__ZN15running_machine30emscripten_get_running_machineEv())
and finds the files under /nvram/<machine>/ in Emscripten's file system; written there before start, MAME loads them.
